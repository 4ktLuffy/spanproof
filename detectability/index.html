Which AI agent failures can Sentry detect today?

With AI data on, Sentry's spans caught every tool loop, retry storm, dead end and cut-off answer that happened, except cut-off answers in OpenAI Agents and Pydantic AI. With AI data off, tool loops went undetected in all 4 setups measured that way. Empty answers were never detectable, and the silent tool error never happened because the model always noticed it.

Why not: the missing data, and where the SDK decides

  1. Tool loop needs the tool arguments. Missing: gen_ai.tool.call.arguments (Node) / gen_ai.tool.input (Python). A loop is the same tool called with the same arguments again and again. Without the arguments, repeated calls cannot be told from normal retries with new inputs. Recorded only when AI data is on.
    Python LangGraph (LangChain callback) · Python OpenAI Agents · Python Pydantic AI · Node LangChain/LangGraph: ai/langchain/index.js:182-184 · Node Vercel AI: getRecordingOptions, vercel-ai-dc-subscriber.js:470-490
  2. Silent tool error needs the tool result. Missing: gen_ai.tool.call.result (Node) / gen_ai.tool.output (Python). A tool that returns an error message as normal output does not set an error status. Only the result text shows it. Recorded only when AI data is on.
    Python LangGraph (LangChain callback) · Python OpenAI Agents · Python Pydantic AI · Node LangChain/LangGraph: ai/langchain/index.js:203-208 · Node Vercel AI: vercel-ai-dc-subscriber.js:297-301
  3. Silent tool error and empty answer need the answer text. Missing: gen_ai.output.messages / gen_ai.response.text. To tell "the agent passed on bad data" from "the agent said it failed", the final answer has to be on a span. Recorded only when AI data is on.
    Python LangGraph (LangChain chat model end) · Python LangGraph agent span · Python OpenAI Agents · Python Pydantic AI · Node: resolveAIRecordingOptions, ai/core/utils.js:9-16
  4. Cut-off answer needs the finish reason, and two Python integrations never record it. Missing: gen_ai.response.finish_reasons. The provider says the answer stopped at the token limit (length / max_output_tokens). The OpenAI Agents and Pydantic AI integrations set usage, model and output on the LLM span but never the finish reason, so this is missed even with AI data on.
    OpenAI Agents update_ai_client_span · Pydantic AI update_ai_client_span
  5. Empty answer is recorded as "nothing". Missing: gen_ai.output.messages (no length or empty marker). When the model returns no text, the Vercel AI integration writes no output attribute at all. An empty answer then looks exactly like an answer that was not recorded, so a detector cannot call it empty.
    Node Vercel AI: buildOutputMessages, vercel-ai-dc-subscriber.js:402-405

How it was measured

  • Real agents (OpenAI Agents SDK, Pydantic AI, LangGraph, LangGraph.js, Vercel AI SDK 7) on Groq openai/gpt-oss-20b, run through the assessment harness's own runner with Sentry's SDKs installed as users would.
  • Faults were injected only through tools, step and token limits, and the provider (three HTTP 500s). The model was never told to fail.
  • What really happened in each run comes from the program's own log (tool calls, arguments, answer, how it ended) and the recorded provider exchanges, never from Sentry's spans.
  • 24 healthy control runs produced 0 false alarms. 144 runs in total.
